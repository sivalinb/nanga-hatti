# Contributing

Start with an issue describing the problem, expected behavior and evidence. Run the workflow tests and the authored eval suite after changing graph nodes, tool contracts or source records. Record actual provider modes when evaluating live changes; a fallback is not a live success.

For context records, provide a primary publication, an original brief summary, stable fact IDs and a precise link. A valid ID does not establish relevance or cultural authority. Do not add disputed origin claims, generated low-resource translations, private archive material, sacred knowledge or recordings without the appropriate contributor/community agreement. Different communities should define their own content and access practices.

The best next contribution is a small pilot with willing contributors and fluent speakers: check naming, local terms, context relevance, accessibility and how useful the review process feels. Collect consented examples for future evals. Keep identifying content out of public engineering fixtures and telemetry.
